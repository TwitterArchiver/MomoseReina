以下是关于 Cloudflare 2025年11月18日服务中断事故的总结：
事故概览
* 时间： 2025年11月18日 11:20 UTC 至 17:06 UTC。
* 现象： Cloudflare 核心网络流量出现大规模故障，用户访问客户网站时遇到 HTTP 5xx 错误页面。受影响的服务包括核心 CDN、Turnstile、Workers KV、Dashboard（仪表盘）和 Access。
根本原因 (Root Cause)
* 非网络攻击： 事故并非由 DDoS 攻击或恶意活动引起。
* 数据库权限变更导致配置错误：
* Cloudflare 对其 ClickHouse 数据库集群进行了权限管理更新。
* 这一变更导致 Bot Management（机器人管理）系统使用的“特征文件”生成查询返回了大量重复数据，使文件大小翻倍。
* 内存预分配限制触发崩溃：
* 该特征文件被分发到全网所有边缘节点。
* 负责路由流量的软件（核心代理 FL2）对该文件有预分配的内存限制（上限为 200 个特征，而平时仅使用约 60 个）。
* 由于文件大小超出限制，导致软件发生 Panic（崩溃），进而引发服务中断。
事故处理与误判
* 初期误判： 由于故障表现为间歇性波动（因为 ClickHouse 集群只有部分节点生成了错误文件，导致好坏文件交替分发），且 Cloudflare 的状态页（Status Page）恰好同时也出现了无关的故障，团队最初误以为遭遇了超大规模的 DDoS 攻击。
* 排查与修复：
* 团队最终确认问题源于 Bot Management 的配置文件。
* 14:24 UTC： 停止了错误配置文件的生成和分发。
* 14:30 UTC： 手动部署了已知的旧版正常文件，核心流量开始恢复。
* 17:06 UTC： 所有相关服务（包括 Dashboard 和 Workers KV）的积压负载处理完毕，系统完全恢复正常。
后续改进措施
* 加强对内部生成的配置文件的验证和“硬化”处理（像对待用户输入一样）。
* 为功能特性启用更全局的“Kill Switches”（熔断机制）。
* 防止错误报告（如 Core Dumps）耗尽系统资源。
* 全面审查核心代理模块的错误处理机制。
这是 Cloudflare 自 2019 年以来最严重的一次中断事故，导致了核心流量无法正常路由。官方已为此致歉并承诺改进系统的弹性。
